# fuxi bring-up 状态（2026-10-18）

## 一句话

我们自己编的 Xiaomi 13 (fuxi / SM8550) UEFI 固件能启动，**我们自己的代码能在真机上运行、
拿到帧缓冲、并通过 `ExitBootServices` 进入真正的裸机环境**。

## ExitBootServices 卡了很久，原因有两层

### 第一层：AArch64 的 runtime 内存粒度是 64KB

`edk2/Common/edk2/MdePkg/Include/AArch64/ProcessorBind.h`:

```c
#define RUNTIME_PAGE_ALLOCATION_GRANULARITY  (0x10000)   // 64KB
```

而 x86/EBC/ARM 都是 `0x1000`。高通平台按 4KB 分配 runtime 区，于是
`CoreTerminateMemoryMap` 判定 "A RUNTIME memory entry is not on a proper alignment"
并返回 `EFI_INVALID_PARAMETER`。

**这正是 Renegade 官方从没发布 fuxi 版本的可能原因之一。**

### 第二层：MapKey 在退出过程中立即失效

`CoreExitBootServices` 的实现顺序是：

```c
CoreNotifySignalList (&gEventExitBootServicesGuid);   // 驱动收尾，分配/释放内存
Status = CoreTerminateMemoryMap (MapKey);             // 用旧的 key 校验 → 失效
```

所以调用者手里的 `MapKey` 在回调执行后必然过期。规范的做法是从 BDS/应用上下文调用，
或者反复重取 `GetMemoryMap` 重试。

### 我们目前的解法（实验性补丁，`tools/patch_firmware.py`）

```
补丁1: RUNTIME_PAGE_ALLOCATION_GRANULARITY 0x10000 -> 1   （跳过粒度检查）
补丁2: CoreTerminateMemoryMap 的 MapKey 比对 -> 恒真        （跳过 key 检查）
```

**这两个补丁是实验手段，不是正确修法。** 正确的做法应该是：

- 让平台按 64KB 对齐分配 runtime 区（或把粒度宏改成 4096 并确认内存布局仍满足）
- 从合适的上下文（而非协议通知回调）调用 `ExitBootServices`，并在失败时重取内存图重试

## 下一步（M3 / M4）
